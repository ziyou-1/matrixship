# 单主角整身同款替换设计

## 目标

将原视频中的一个主角替换为用户上传人物的完整外观，包括脸、发型、服装、体型和配饰；保留原片主角的动作、站位、镜头、时序、原音和台词。其他人物、产品和环境保持不变。

## 已确认范围

- 首期只处理一个主角，不提供多人物映射。
- 人物素材至少一张清晰全身图，最多三张不同角度的人物图。
- 用户确认对上传人物素材拥有必要授权。
- 原片动作、空间占位、镜头语言和音频应保留；原片主角外观不应保留。
- 生成失败时不得静默回退为当前的参考图重新生成链路。

## 现状与缺口

当前 `hybrid_v2` 会上传原片段，但在提交参考图视频模型前删除 `source_video_url`。因此远端只收到提示词和参考图，无法可靠执行视频级主角替换。原片人物候选也只是首、中、尾截图，不包含可追踪的主角记录。

LK888 当前模型目录已确认存在 `happyhorse-video-edit`，其输入提示明确要求上传待编辑源视频，并可附带参考图和编辑描述。中心服 `/lk888` 对 JSON 请求透明转发，适合承载该模型所需的源视频字段。

## 方案

### 1. 单主角提取

方案阶段从原视频抽取固定数量关键帧，调用现有 LK888 视觉理解能力返回结构化 `principalActor`：主角描述、最佳帧序号、归一化边界框、置信度和识别依据。客户端按边界框裁出预览图，任务 JSON 保存主角记录和预览路径。

这是用户可审阅的主角定位记录，不把原片人物裁剪图作为远端身份参考，避免把旧人物外观重新注入生成模型。源视频编辑模型仍以完整源片段作为动作、镜头和空间关系依据。

视觉定位失败或低置信度时，页面要求用户在原有候选帧中选择主角参考帧；未确认主角不得提交远端生成。

### 2. 人物素材输入

同款替换页面把现有“三张授权人脸”调整为“主角人物参考图（1-3 张，至少一张全身图）”。任务保存新字段：

```json
{
  "principalActor": {
    "status": "detected|manual|failed",
    "bestFrameIndex": 1,
    "bbox": {"x": 0, "y": 0, "width": 0, "height": 0},
    "confidence": 0.0,
    "previewPath": ""
  },
  "personReferencePaths": ["..."],
  "personReferenceUrls": ["https://..."],
  "principalReplacementMode": "source_video_edit"
}
```

保留旧 `faceSourcePaths` / `faceSourceUrls` 的读取兼容，但新任务不自动走 FaceFusion。整身替换只由源视频编辑模型完成，避免事后换脸破坏用户上传人物的服装和体型。

### 3. 源视频编辑请求

新主角替换模式只使用 `happyhorse-video-edit`。请求必须同时包含公网可访问的源片段和人物参考图，兼容传递 `video_url`、`video_urls`、`reference_video` 与 `params` 内视频字段。客户端仅剥离内部追踪字段，不得删除任何实际源视频字段。

提示词明确约束：

- 仅替换 `principalActor` 对应的一个主角。
- 使用上传人物的全身外观，不复用原主角脸、衣服、体型或配饰。
- 保留原片动作、站位、姿势、镜头、时长、音频和台词。
- 保持其他人物、背景、产品和文字不变。

若 LK888 拒绝源视频字段、未创建任务或返回非视频结果，任务标记为 `principal_video_edit_unavailable` / `principal_video_edit_failed`，停止该片段，不回退到参考图视频模型。

### 4. 质量门禁和人工审核

每段仍执行媒体、音频、首中尾帧和视觉质检；新增主角替换检查：主角外观是否采用上传人物、其他人物是否未被替换、动作/镜头是否仍与源片段一致。任何视觉服务异常降级为人工审核，但源视频模型契约失败必须阻断。

用户确认全部片段后，保持现有拼接、字幕烧录、最终音频检查和资产库入库流程。

## Phase 0 冒烟验证

在接入正式页面前，使用已上传且可公网访问的短源视频片段和已授权人物参考图，对 `happyhorse-video-edit` 发起一次最小请求。验证项：

1. 中心服能透明转发源视频字段。
2. LK888 接受至少一种源视频字段组合并返回 task id。
3. 轮询结果为有效视频，且视频不是纯静态图或空音轨。
4. 失败响应记录脱敏的模型、字段集合、状态码和错误编号；不记录 URL 查询参数、Token 或人物图片内容。

若未拿到 task id，本次实现只保留模型契约探针和明确阻断，不对外宣称已经实现整身替换。

## 非功能要求

| 项目 | 约束 |
| --- | --- |
| 并发 | 单客户端、单主角、片段串行，保持跨片段连续性。 |
| 片段 | 约 8 秒，单段请求时长继续钳制为 1-15 秒。 |
| 素材 | 人物图 1-3 张，至少一张全身图；只传 HTTPS 公网 URL。 |
| 显存 | 本方案不新增本地深度学习模型；GPU 显存增量为 0 MiB。 |
| 延迟 | 主角定位一次视觉调用；每段一次异步视频编辑请求，沿用 150 次、4 秒轮询上限。 |
| 可观测 | 任务 JSON 和 JSON 日志记录 `principalActor`、模型、字段名、阶段、errorId、质量检查。 |
| 回滚 | 设置 `VIDEO_REPLACE_PRINCIPAL_REPLACEMENT=0` 回到原 `hybrid_v2` 参考图链路；不删除已有任务。 |
| 隐私 | 完成、失败或取消后清理人物上传素材和临时主角预览；日志不写入人脸/全身图内容或签名 URL。 |

## 影响文件

- `backend/matrix_native_client.py`：页面输入、主角提取、任务字段、模型请求、质检和结构化日志。
- `tests/test_video_replacement_v2.py`：提取、请求契约、失败阻断、素材门禁和 UI 文案测试。
- `backend/.env.example`、`backend/.env.prod`、`docs/DEPLOYMENT.md`：环境开关及回滚说明。
- `docs/ARCHITECTURE.md`、`docs/API_REFERENCE.md`、`docs/TROUBLESHOOTING.md`、`docs/IMPLEMENTATION.md`、`CHANGELOG.md`：数据流、任务契约、排障、行号和变更记录。

## 不在范围内

- 多主角/多人映射。
- 本地逐帧人体分割或视频抠像模型。
- 将未经授权人物素材用于替换。
- 在 LK888 源视频模型不可用时自动切换为参考图重生成并伪装成功。

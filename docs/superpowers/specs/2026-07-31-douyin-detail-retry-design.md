# 抖音详情接口连接重试设计

## 目标

内容采集后的抖音视频在进入“分解视频”前，需要再次读取作品详情。该请求出现临时 DNS、TLS、连接或读取超时时，系统应自动恢复；持续失败时，页面只展示可操作的中文提示，技术细节进入脱敏结构化日志。

## 用户契约

- 首次请求失败后最多重试 3 次，总请求次数最多 4 次。
- 连接超时 8 秒，读取超时 15 秒，重试等待依次为 1、2、4 秒。
- 只重试 `requests.ConnectionError` 和 `requests.Timeout`；HTTP 业务响应及 JSON 解析错误保持原行为，不自动重试。
- 最终网络失败返回 `douyin_detail_network_failed`，分解页面精确显示“抖音连接暂时失败，请重试”。
- 响应不包含原始异常或堆栈；JSON 日志保留 `errorId`、尝试次数、超时、异常类型、固定主机和作品编号指纹，不记录 Cookie、Token、签名值、完整 URL 或作品编号原文。

## 方案对比

| 方案 | 覆盖面 | 风险 | 结论 |
|---|---|---|---|
| 在 `DouyinAPI.get_work_info` 内重试，下载接口归一化错误 | 所有作品详情调用 | 小，维持现有调用关系 | 采用 |
| 只在 `/api/douyin/download` 外层重试 | 只覆盖下载 | 其他详情调用仍不稳定 | 不采用 |
| 给全部抖音接口增加通用重试器 | 全部抖音 API | 改动面过大，可能重复业务请求 | 不采用 |

## 非功能性需求

- QPS：不改变现有限流与并发模型；单个失败请求最多产生 4 次详情调用。
- 延迟：正常成功无额外等待；连续失败最坏等待包含 7 秒退避及每次独立连接/读取超时。
- 资源：不引入新线程、进程、显存或常驻缓存，内存增量可忽略。
- 可观测：每次最终失败生成唯一 `errorId` 和脱敏 JSON 日志。
- 可回滚：恢复本次三个生产文件即可回到旧行为；无数据库、Docker、环境变量或 `migration.sql` 变更。

## 测试策略

使用假响应验证临时失败后成功、4 次均失败、HTTP 业务响应不重试、API 502 契约、日志脱敏和客户端完整中文提示。真实抖音下载依赖账号状态，不纳入自动测试。

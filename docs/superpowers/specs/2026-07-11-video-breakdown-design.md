# 视频深度分解功能设计

## 目标

在本地客户端的「内容采集」中新增「分解」入口。用户粘贴或选择抖音/小红书视频链接后，点击一次「分解」，系统自动完成下载、入库、跳转到「分解视频」页面，并生成临时深度拆解报告。报告只在当前页面展示，不写入资产库或知识库；用户可手动下载为本地 Markdown 文件。

## 用户流程

1. 用户在「内容采集」页选择平台，粘贴视频/笔记链接。
2. 点击「分解」按钮。
3. 客户端通过现有本机浏览器任务调用下载接口。
4. 下载成功后，使用返回的本地视频文件路径进入「分解视频」页。
5. 「分解视频」页显示进度：下载完成、抽帧、OCR、音频转写、AI 汇总。
6. 分析完成后展示报告，并提供「下载报告」按钮。

## 深度分析内容

报告包含：

- 视频基础信息：来源平台、源链接、本地文件路径、时长、分辨率。
- 内容总览：一句话总结、视频类型、核心卖点、目标用户。
- 时间轴镜头拆解：按关键帧或时间段列出画面、人物、产品、动作、字幕、道具、场景。
- 字幕与口播：优先使用本地 OCR 和音频转写结果；失败时基于关键帧做视觉推断并标注缺失。
- 营销结构：开头钩子、痛点、解决方案、证据、转化动作。
- 爆点分析：吸睛点、节奏、情绪、可复刻原因。
- 仿拍脚本：镜头顺序、画面要求、口播参考、拍摄注意事项。
- Agent.模式提示词：用于生成同款风格视频的结构化提示词。

## 技术方案

### 客户端 UI

- 在 `ContentPage` 的「下载」「看评论」旁新增「分解」按钮。
- 新增左侧导航页「分解视频」，位置放在「内容采集」下面。
- 通过 `BRIDGE.payload` 传递下载结果和视频路径，跳转到新页面。

### 下载与入库

- 复用现有 `submit_local_task(pf + ".download", ...)`。
- 下载接口已导入资产库，但本功能不保存分析报告。
- 若下载结果中没有可用视频文件，页面显示结构化错误：`no_video_file`、源链接、平台、下载返回摘要。

### 视频处理

- 使用已有 `imageio-ffmpeg` 提供的 ffmpeg。
- 抽取关键帧：按时长均匀抽取，默认最多 16 帧；短视频至少抽 6 帧。
- 获取基础信息：通过 ffprobe 或 ffmpeg 输出解析时长、分辨率。
- OCR：优先使用可选 Python OCR 依赖；若依赖不存在，降级为“未启用 OCR”，不阻断主流程。
- 音频转写：先导出音频片段；若当前项目没有稳定的转写接口，则降级为“未启用音频转写”，不阻断主流程。

### AI 汇总

- 复用 `lk888_vision` 分析关键帧，复用 `lk888_chat` 汇总 OCR、转写和视觉分析。
- API Key 不写入代码，继续走现有中心服 `/lk888` 反代。
- 错误信息脱敏，不展示密钥、Cookie、完整内部堆栈。

## 降级策略

- 下载失败：停在「分解视频」页，展示下载失败原因。
- 找不到视频文件：提示该链接未下载到视频，可能是图集、权限、风控或平台限制。
- 抽帧失败：展示错误并允许用户换链接重试。
- OCR 不可用：继续视觉分析，报告中标记“未启用 OCR”。
- 音频转写不可用：继续视觉分析，报告中标记“未启用音频转写”。
- AI 调用失败：保留已抽帧和本地分析摘要，提示模型错误。

## 测试策略

- 单元测试：验证下载结果中视频文件选择逻辑、报告 Markdown 生成逻辑、降级状态文案。
- 冒烟测试：使用一个本地小 mp4 跑抽帧和报告生成骨架，不依赖真实平台下载。
- 手工验证：在客户端输入视频链接，点击「分解」，确认自动下载、跳转、展示报告、下载报告。

## 回滚方案

- 回滚 UI：移除「分解」按钮和「分解视频」导航项。
- 回滚逻辑：新增逻辑独立于现有下载、资产库和内容采集主流程；关闭入口即可恢复现状。
- 数据影响：分析报告不长期保存，不产生数据库迁移。

## 非目标

- 不把报告自动写入知识库。
- 不保证下载到平台上传前的原始母版视频。
- 不在第一版实现批量分解。

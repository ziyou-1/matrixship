# 同款替换内嵌媒体与分项重生成设计

## 目标

修复漫剧视频已经生成并返回地址，但本地客户端因受保护媒体下载未携带鉴权而将片段误判为失败的问题；同时把片段表调整为可直接检查和分项重生成的工作台。

新交互必须满足：

- 视频生成成功后直接在“视频”列内嵌播放，不显示公网链接。
- 点击首帧或尾帧时，在客户端内预览图片，不打开浏览器或公网链接。
- 首帧和尾帧分别提供独立的“重新生成”入口。
- 重新生成任一帧后，只更新该图片，并把现有视频标记为“待重新生成”；不自动提交视频任务。
- 每段提供明确的“重新生成视频”入口，使用当前最新首帧、尾帧、口播稿和音频重新生成。
- 页面底部“重试失败片段”批量重新生成全部失败片段的视频。
- 重生成前使用普通确认提示，不显示计费类型、任务数量、预计金额或“按实际模型计费”等额外说明。

声音来源采用以下明确契约：

- `auto`（界面显示“自动”）直接保留本次生成视频自带的声音，不读取原视频音轨，也不生成或混入 AI TTS。
- 旧任务中的 `source`、`origin`、`original` 和 `source_audio` 只做兼容归一化，统一按 `auto` 执行。
- `tts`（界面显示“AI 音色配音”）才根据口播稿和所选音色生成 TTS，并在需要时替换模型音轨。
- 自动模式和 AI 音色模式必须随每次单段视频重生成提交，不能依赖远程项目的历史默认值。

## 现状与根因

远程漫剧任务完成后，本地客户端先把 `videoUrl` 写入片段，再使用通用下载函数获取视频。受保护的 `/data/uploads/comic-drama/` 媒体路由要求漫剧登录凭证，而通用下载没有携带 Bearer Token，因此返回 HTTP 401。

界面读取已经写入的 `videoUrl`，所以视频列会出现公网链接；任务完成状态则依赖本地下载和媒体校验，因此最终显示失败。这是状态写入顺序和下载鉴权共同导致的误导，不是视频模型生成失败。

## 方案选择

| 方案 | 展示方式 | 稳定性 | 鉴权风险 | 结论 |
| --- | --- | --- | --- | --- |
| A | 鉴权下载到本地后内嵌播放和预览 | 高 | 客户端统一处理 | 采用 |
| B | 播放器直接加载远程媒体地址 | 中 | Token 过期或请求头缺失会失败 | 不采用 |
| C | 表格只显示缩略图，点击弹出播放器 | 高 | 可控 | 不符合视频列直接展示要求 |

## 界面设计

片段表保持六列：`序号 | 口播稿 | 首帧图 | 尾帧图 | 视频 | 操作`。

### 首帧与尾帧

- 单元格显示当前图片缩略图和重新生成图标按钮。
- 点击缩略图打开客户端图片预览窗口，显示本地缓存的原图。
- 图片预览窗口支持适应窗口、原始尺寸查看和关闭，不加载网页。
- 点击重新生成按钮时，提示“确定重新生成片段 X 的首帧/尾帧吗？”。
- 确认后通过 `frameIndex=1` 或 `frameIndex=2` 仅提交当前这一张图片的生成任务。
- 生成成功后替换对应任务 ID、远程地址和本地缓存文件，并保留上一版本元数据到片段重试历史。

### 视频

- 未生成时显示“待生成”。
- 首帧或尾帧更新后显示“待重新生成”。
- 生成中显示当前阶段和实时耗时。
- 远程生成完成后先鉴权下载并执行媒体校验。
- 校验成功后在视频列内嵌播放器，提供播放、暂停、进度拖动、音量和全屏能力，默认不自动播放。
- 不在单元格、工具提示或错误提示中展示公网媒体地址。

### 操作

- 每行操作按钮明确命名为“重新生成视频”，不再使用含义模糊的“重生”。
- 点击后提示“确定重新生成片段 X 的视频吗？”。
- 确认后使用当前最新首帧、尾帧、口播稿和音频提交新的视频任务。
- 新视频校验成功后替换播放器内容；旧视频任务和本地路径写入重试历史，不静默丢失追踪信息。
- 页面底部“重试失败片段”保留，确认后批量重新生成所有失败片段的视频。

## 状态模型

每个片段至少区分以下媒体状态：

- `pending`：尚未生成。
- `generating_frame`：首帧或尾帧正在重新生成。
- `video_stale`：首尾帧发生变化，已有视频不再对应当前帧。
- `generating_video`：视频正在重新生成。
- `downloading_video`：远程视频完成，正在鉴权下载。
- `done`：本地视频已下载并通过校验，可播放和合成。
- `failed`：图片或视频生成失败。
- `download_failed`：远程视频成功，但本地鉴权下载或校验失败。

重新生成首帧或尾帧时，不删除旧视频文件，但必须把它从“当前可合成视频”中失效，防止旧视频与新帧混用。最终合成只接受全部片段状态为 `done` 且本地媒体校验通过的当前视频。

## 下载与鉴权

- 增加漫剧媒体专用下载入口，不修改其他平台共用的普通下载函数。
- 漫剧受保护媒体下载复用 `ComicProjectAdapter` 当前有效的 Bearer Token。
- Token 失效返回 401 时只允许刷新一次登录凭证并重试下载，避免无限循环。
- 普通公网地址继续使用现有无鉴权下载方式。
- 下载使用临时文件，完成媒体校验后原子替换目标文件；失败时删除临时文件并保留上一版可用视频。
- 远程任务已完成而本地下载失败时，错误文案显示“远程视频已生成，本地获取失败”，不得误报为模型生成失败。

## 漫剧接口兼容扩展

当前漫剧 `POST /api/v1/comic-drama/storyboards/{storyboard_id}/generate-image` 在首尾帧模式下固定提交两张图片。远程 `server.py` 增加可选参数：

- `frameIndex=1`：只生成首帧。
- `frameIndex=2`：只生成尾帧。
- 不传 `frameIndex`：保持原行为，一次生成首帧和尾帧两张。
- 传入其他值：返回 JSON Schema 参数校验错误，不提交模型任务、不计费。

单帧请求继续使用现有分镜、角色、场景、道具和图片模型配置，只筛选对应帧提示词；任务结果仍以原有 `frame_index` 元数据回写项目。该扩展不得改变漫剧网页、批量生成或现有首尾帧双图请求的行为。

## 重生成数据流

### 单帧重生成

1. 用户点击首帧或尾帧重新生成。
2. 客户端显示普通确认提示。
3. 保存当前图片任务和媒体信息到 `retryHistory`。
4. 携带对应 `frameIndex` 提交单张图片生成任务并轮询。
5. 鉴权下载图片到本地缓存并校验。
6. 更新对应首帧或尾帧字段。
7. 将片段设为 `video_stale`，保留旧视频仅供追溯，不参与合成。

### 视频重生成

1. 用户点击每行“重新生成视频”，或使用底部批量重试入口。
2. 客户端显示普通确认提示。
3. 保存当前视频任务和媒体信息到 `retryHistory`。
4. 使用最新首帧、尾帧、口播稿和音频提交视频任务。
5. 远程完成后使用漫剧凭证下载视频。
6. 执行视频流、音频流和时长校验。
7. 校验通过后设置为 `done` 并刷新内嵌播放器。

### 声音模式

客户端在视频生成请求中显式传递规范化后的 `audio_mode`。远程漫剧服务在 `audio_mode=auto` 时跳过分镜 TTS 准备和备用模型 TTS 重混，直接把模型返回的视频作为结果并记录 `audioSource=provider_generated`；在 `audio_mode=tts` 时保留现有分镜 TTS 准备、音频时长匹配和备用模型强制 TTS 重混逻辑。该判断只影响 Matrix 同款替换显式提交的声音模式，不改变未携带该字段的现有漫剧网页请求。

## 可观测、可回滚、可追溯

- 所有生成、下载、凭证刷新和媒体校验异常写入脱敏 JSON 结构化日志。
- 日志记录任务 ID、项目 ID、片段序号、分镜 ID、媒体类型、HTTP 状态和错误编号；不记录 Token、完整请求头或带敏感参数的地址。
- `retryHistory` 保存被替换的任务 ID、模型、结果地址摘要、本地路径、操作类型、操作时间和失败原因。
- 本地代码改动限制在漫剧媒体展示、下载和重生成入口；远程代码只增加 `frameIndex` 兼容分支，不修改模型选择、提示词生成算法或现有项目数据。
- 发布远程 `server.py` 前保存带时间戳的上一稳定版本备份；回滚时恢复该文件并重启 `ai-canvas.service`。参数缺省行为不变，因此本地客户端和远程服务可以分别回滚。
- 任务 JSON 新增字段采用可选读取，旧客户端可忽略，不要求数据库迁移。
- 本地客户端不自动重启，由用户手动重启后生效。远程漫剧服务修改部署后必须重启 `ai-canvas.service` 并通过健康检查；中心服不需要重启。

## 测试策略

### 冒烟测试

- 使用假漫剧项目和三个假片段，模拟远程视频已完成但裸下载返回 401。
- 验证专用下载携带鉴权后成功保存、校验并把片段设为 `done`。
- 失败点和修复结论写入 `docs/TROUBLESHOOTING.md`。

### 自动测试

- 受保护视频下载携带 Bearer Token；401 时刷新一次后重试。
- 下载失败使用 `download_failed`，不误报模型失败。
- 视频 URL 不直接写入表格文本。
- 视频列创建内嵌播放器且默认不自动播放。
- 点击首尾帧打开本地预览，不调用公网打开函数。
- 首帧和尾帧按钮只提交对应图片任务。
- 远程接口不传 `frameIndex` 时仍生成两张；传 `1` 或 `2` 时只生成对应一张；非法值不产生任务。
- 单帧成功后片段进入 `video_stale`，旧视频不参与合成。
- 单段视频重生成使用最新帧、台词和音频。
- 自动模式不调用 TTS、不执行 TTS 重混并保留生成视频自带声音；AI 音色模式继续使用口播稿 TTS。
- 批量重试只处理失败片段。
- 旧任务 JSON 仍可打开查看。

### 验收测试

- 三个片段均能直接查看首帧、尾帧和视频，不出现公网链接文本。
- 任意重生成一张首尾帧后，视频明确显示待重新生成。
- 重新生成视频成功后播放器更新，最终合成使用最新视频。
- 远程视频完成但下载失败时给出准确错误提示和可追踪错误编号。

## 非功能性要求

- 表格刷新和图片预览不得阻塞 UI 主线程超过 100 毫秒。
- 视频下载、图片下载和媒体校验必须在后台执行。
- 每个片段只实例化一个当前播放器；页面刷新时释放旧播放器资源，避免句柄和内存累积。
- 单次 401 最多刷新凭证并重试一次。
- 所有新增状态写盘必须保持任务 JSON 原子更新语义。
- 不新增 GPU 显存占用；客户端内存增量以当前可见片段播放器为主，并在离开页面时释放。
- 远程单帧接口延迟和显存上限不得高于现有单张图片模型调用；不改变现有双帧请求的并发和 QPS 限制。

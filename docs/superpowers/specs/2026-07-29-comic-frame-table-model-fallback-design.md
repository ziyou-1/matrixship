# 同款替换双帧表格与视频模型回退设计

## 目标

修复漫剧项目模式下分镜表格错位、双帧状态缺失、相对媒体地址下载失败，以及 Seedance 真人素材被拒后备用模型不合适的问题。新任务继续使用漫剧生成器的首尾帧流程，不恢复旧失败任务。

## 已确认范围

- 表格列改为：`序号 | 口播稿 | 首帧图 | 尾帧图 | 视频 | 操作`。
- 删除“流程图生成”列。
- 首帧图和尾帧图展示漫剧生成器返回的真实图片缩略图。
- 口播稿编辑器必须受表格单元格约束，不得覆盖相邻列。
- 视频模型依次回退：
  `Seedance -> Vidu Q3 多参考 -> 万相 2.7 首尾帧 -> Kling V3 Omni 首尾帧 -> PixVerse 首尾帧`。
- 不接入视频口型同步模型。备用模型生成后继续沿用现有音频合入逻辑，不能承诺逐字口型同步。
- 不恢复当前失败任务。修复后使用同一抖音原视频和指定人物、产品、场景图新建仅含前 3 个片段的真实测试任务。
- 不自动重启本地客户端；远程漫剧服务部署后按需重启 8777。

## 方案选择

采用本地与远程分工方案：

- 本地客户端负责双帧任务等待、媒体 URL 规范化、任务 JSON 持久化和表格展示。
- 远程漫剧服务器负责模型回退、计费补偿、防重复提交和模型实际状态记录。
- 不把模型回退移到客户端，避免本地超时后重复下单和重复计费。
- 不重做完整漫剧 API，控制本次改动范围。

## 本地客户端设计

### 双帧任务

图片生成接口返回多个任务 ID 时，客户端保留并等待首帧、尾帧两个任务。片段记录新增兼容字段：

- `startFrameTaskId`
- `endFrameTaskId`
- `startFrameUrl`
- `endFrameUrl`

旧字段 `flowchartUrl` 继续读取，作为旧任务首帧兼容来源，不再作为新表格列名。

只有所需双帧均完成后才进入视频生成。若远程分镜已有双帧或视频结果，客户端先恢复远程结果，避免重复生成。

### 媒体地址

远程返回 `/uploads/...` 等相对地址时，统一基于漫剧服务器地址补全为绝对 URL，再用于下载、缩略图展示和任务持久化。已有绝对 HTTP(S) 地址保持不变。

### 表格布局

- 序号列固定窄宽。
- 口播稿列占用剩余空间，编辑器不设置超出单元格的最小宽度。
- 首帧、尾帧、视频和操作列使用固定稳定宽度。
- 行高固定为可容纳缩略图和编辑器的高度。
- 使用像素级滚动，刷新状态不得改变列宽或造成翻页式跳动。

## 远程模型回退设计

模型顺序使用配置化列表，默认值为：

1. `doubao-seedance-2-0-260128`
2. `vidu/viduq3-mix_reference2video`
3. `wan2.7-shouweizhen`
4. `kling-v3-omni-shouweizhen`
5. `pixverse-v6-shouweizhen`

环境变量不得包含密钥，模型链通过普通配置读取。显式空配置可关闭自动回退，便于快速回滚。

### 回退条件

- 真人隐私审核拒绝、参数明确不支持、远程任务明确失败：进入下一个模型。
- 网络超时、HTTP 502、限流：先使用原任务 ID 查询状态，并执行有限次数退避重试。
- 只有确认原任务没有成功结果后才提交下一个模型。
- 每个模型每个分镜最多提交一次，任务记录提交幂等键、请求模型、实际模型、失败原因和回退历史。
- Seedance 因真人隐私拒绝时沿用现有失败扣费补偿，再对备用模型独立计费。

### 模型参数适配

每个模型使用独立参数适配器：

- Vidu Q3 使用多参考图输入，优先携带首帧、尾帧以及允许数量内的角色、场景、道具参考图。
- 万相、Kling Omni、PixVerse 使用首尾帧输入，并保持提示词、时长和画幅。
- 不向不支持的模型发送音频或多余字段，避免参数校验失败。

## 可观测性与错误处理

结构化日志至少包含：

- `event`
- `project_id`
- `storyboard_id`
- `local_job_id`
- `requested_model`
- `actual_model`
- `fallback_index`
- `remote_task_id`
- `error_code`
- `elapsed_ms`

日志不得记录 API Key、完整鉴权头或用户隐私素材内容。客户端片段状态保存首尾帧任务、视频任务、实际模型、回退历史和错误编号，便于本地与漫剧项目交叉排查。

## 测试策略

### 自动化测试

先写失败测试并确认失败，再实现：

- 多任务 ID 能分别映射首帧和尾帧。
- 客户端等待两个图片任务后才提交视频。
- `/uploads/...` 能正确补全并下载。
- 旧 `flowchartUrl` 任务仍能打开。
- 表格列名、列数、列宽策略和编辑器尺寸约束正确。
- Seedance 拒绝后首先切 Vidu。
- Vidu、万相、Kling Omni、PixVerse 按顺序回退。
- 暂时性错误先查询原任务，不立即重复下单。
- 明确失败才切换，所有候选失败后保留完整回退历史。

### 真实冒烟测试

- 原视频：当前任务所用抖音视频 `7657719110507299769`。
- 仅生成前 3 个片段。
- 人物图：`E:/Desktop/数字人/1.png`。
- 产品图：`E:/Desktop/数字人/美妆主播带货图生成需求-7.png`。
- 场景图：`E:/Desktop/数字人/汽车之家.jpg`。
- 同时检查本地任务 JSON、客户端状态事件、远程漫剧项目、图片任务和视频任务。
- 验收标准：三段均能展示首尾帧；文本框不越界；生成视频可下载和播放；发生 Seedance 真人拒绝时实际模型首先变为 Vidu；无重复计费提交。

## 部署与回滚

- 修改远程 `server.py` 前创建带时间戳备份。
- 部署后只重启漫剧服务 8777，并检查健康接口。
- 不自动重启本地客户端，由用户手动重启后验证界面。
- 回滚时恢复远程备份并重启 8777；本地代码可恢复到改动前版本。
- 本次不新增数据库表，不需要业务数据库迁移；`migration.sql` 记录“无迁移”。
- 更新 `CHANGELOG.md`、`docs/IMPLEMENTATION.md`、`docs/TROUBLESHOOTING.md` 和相关 API/部署说明。

## 非功能性要求

- 同一分镜同一模型提交 QPS 不超过 1，瞬时请求通过退避处理。
- 客户端状态刷新不高于每秒一次，页面操作不得被远程轮询阻塞。
- 本地 URL 补全和表格刷新目标延迟低于 100 ms。
- 不涉及本地 GPU 推理，新增显存占用为 0。
- 错误率超过 1% 时停止扩大真实测试，并按回滚流程恢复远程稳定版本。

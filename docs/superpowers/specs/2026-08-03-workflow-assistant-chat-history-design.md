# 工作流助手聊天与分析结果保留设计

## 1. 背景

当前工作流助手页面将聊天内容保存在 `AgentChatPage.history` 内存变量中。页面在当前实例内可以连续显示聊天和视频分析结果，但页面重建、账号切换或客户端重启后，历史内容会丢失。

本次需求是：用户离开工作流助手后再次返回，仍能看到之前的聊天内容、采集结果、完整视频拆解文本和“按这条改造生成”入口。历史按当前登录账号隔离，最多保留最近 100 轮对话。

## 2. 目标

- 在当前页面中继续实时显示用户消息、助手回复和视频分析结果。
- 页面重新打开时恢复最近 100 轮聊天。
- 恢复每条分析结果关联的同款替换入口。
- 不同账号之间不能看到彼此的工作流助手聊天。
- 写入失败时不阻断聊天和视频分析，仅记录脱敏结构化日志。

## 3. 非目标

- 不保存私信 / AI 销售对话。
- 不把工作流助手聊天同步到中心服务器。
- 不保存 Cookie、Token、Authorization、完整签名 URL 或其他凭据。
- 不替代资产库中的视频、文本和结构化分析文件；资产库仍是分析产物的长期存储位置。

## 4. 推荐方案

使用当前账号数据目录下的：

```text
workflow_assistant_history.json
```

路径通过现有 `data_dir()` 获取，保证沿用当前账号作用域。文件使用版本化结构：

```json
{
  "version": 1,
  "messages": [
    {
      "role": "user",
      "content": "用户请求",
      "createdAt": "2026-08-03T00:00:00Z"
    },
    {
      "role": "assistant",
      "content": "完整采集与视频拆解结果",
      "replacementPayloads": [],
      "createdAt": "2026-08-03T00:00:01Z"
    }
  ]
}
```

每次新增用户消息或助手最终回复后，先写入临时文件，再使用原子替换更新正式文件。只保留最近 100 轮用户/助手对话，状态进度消息不单独恢复，避免重新打开页面后显示已经结束的“运行中”进度。

## 5. 页面恢复流程

1. `AgentChatPage` 创建完成后读取当前账号的历史文件。
2. 校验 JSON 版本、消息角色和文本类型；无效文件按空历史处理，并记录错误编号。
3. 按顺序重建用户气泡和助手气泡。
4. 对助手消息中的 `replacementPayloads` 重建“按这条改造生成”卡片。
5. 当前账号发生变化时，重新加载新账号历史，禁止沿用旧账号内存内容。
6. 新消息仍然立即显示在当前页面，保存失败不影响本次模型调用结果展示。

## 6. 错误处理与可观测性

- 文件不存在：按首次使用处理，不记错误。
- JSON 损坏或版本不支持：忽略损坏历史，输出结构化事件 `workflow_assistant_history_load_failed`。
- 原子写入失败：保留当前页面内存内容，输出 `workflow_assistant_history_save_failed`。
- 日志只记录账号作用域摘要、消息数量、文件大小、阶段和 `errorId`，不记录消息正文和敏感凭据。

## 7. 测试策略

- 单元测试：历史文件路径按账号隔离。
- 单元测试：写入后可以读取最近 100 轮，旧消息被淘汰。
- 单元测试：助手回复中的 `replacementPayloads` 可以恢复改造卡片数据。
- 单元测试：损坏 JSON 不阻断页面创建。
- 语法检查：`py_compile`。
- 本地 UI 冒烟：工作流助手发送一条请求，切换到其他页面，再返回，确认聊天和分析结果仍在。

## 8. 回滚

回滚范围仅包括工作流助手历史读写代码、专项测试和相关文档。删除或忽略 `workflow_assistant_history.json` 不会影响资产库视频、文本或结构化分析文件。

# 账户中心消费账单看板设计

## 1. 背景

当前本地客户端账户中心只展示余额和最近消费流水，中心服 `GET /api/billing/ledger` 也只返回内存账本中最近 100 条记录，无法准确提供指定期间内的消费统计、趋势、模型类型分布和分页明细。

本次参考漫剧生成器消费账单的结构，保留本地客户端现有视觉体系和角色权限，建立由中心服统一计算、本地客户端只负责展示的账单看板。

## 2. 目标

- 展示云豆余额、期间总消耗、日均消耗、单条视频平均消耗四项指标。
- 默认查询最近 30 天，并支持自定义日期范围。
- 提供按日、按月的消费柱状趋势图。
- 提供视频生成、图片生成、配音、其他四类消费分布。
- 提供可筛选、可分页的扣费明细。
- 保持管理员、企业用户和普通用户现有功能权限不变。
- 保证统计数据可追溯到原始消费记录，异常可通过脱敏结构化日志定位。

## 3. 非目标

- 不展示“折扣共节省”。
- 不调整充值、兑换码、手机绑定、管理员用户管理的业务逻辑或权限。
- 不改变现有扣费、退款和充值流程。
- 不修改漫剧生成器远程服务。
- 不新增数据库表；若实现核查发现现有字段无法满足追溯要求，必须另行确认后再设计迁移。

## 4. 用户与权限

- 普通用户和企业用户：显示账单指标、趋势、类型分布和扣费明细，不显示管理员账户管理功能。
- 平台管理员：显示全部账单内容，并继续显示现有充值、兑换码、手机绑定、用户管理等账户管理功能。
- 服务端始终以当前登录用户为查询主体，不接受客户端传入任意用户 ID。管理员若沿用现有用户管理接口，其授权规则保持不变。

## 5. 统计口径

### 5.1 时间范围

- 默认范围为当前日期向前 29 个自然日，共 30 天。
- 日期按中心服配置的业务时区解释，默认 `Asia/Shanghai`。
- 开始日期和结束日期均包含在统计范围内。
- 自定义范围必须满足开始日期不晚于结束日期，服务端允许的最大跨度固定为 366 天；超出范围返回明确的参数错误。

### 5.2 消费范围

- 纳入消费统计：视频生成、图片生成、配音、其他消费。
- 不纳入消费统计：充值和退款。
- 充值和退款仍进入扣费明细，并显示实际余额变动和状态。
- 退款采用两条明细记录：原扣费保留为负金额“已扣费”，退款另列为正金额“已退款”；两条记录通过同一任务 ID 或请求 ID 关联，不覆盖原扣费记录。
- 上线后的微信充值、兑换码充值和管理员手动充值都必须写入可追溯账单。历史记录只展示能够由账本、充值订单或兑换码使用记录可靠还原的数据；缺少准确时间或扣后余额的旧管理员充值不伪造、不回填。
- 同一业务记录不得同时从内存账本和 `model_usage_logs` 重复计入。优先使用稳定业务键去重；业务键缺失时使用用户、请求 ID、金额、时间和类型组成的保守复合键，并记录去重告警。

### 5.3 指标公式

- 云豆余额：查询时当前用户的实时余额。
- 期间总消耗：统计范围内有效消费记录实扣金额之和。
- 有消费记录的天数：统计范围内至少存在一笔有效消费的自然日数量。
- 日均消耗：`期间总消耗 / 有消费记录的天数`；没有消费时返回 `0`。
- 单条视频平均消耗：`视频生成消费总额 / 已计费视频任务数量`；没有已计费视频任务时返回 `0`。
- 同一视频任务发生多次模型扣费时，消费金额全部计入分子，但任务数量按稳定任务 ID 去重后计入分母。

### 5.4 分组规则

- 按日：以自然日为桶，范围内无消费日期补零。
- 按月：以自然月为桶，范围内无消费月份补零。
- 类型分布仅返回视频生成、图片生成、配音、其他四类；未知模型或历史类型归入“其他”。

## 6. 架构与数据流

### 6.1 职责边界

- 中心服是统计口径的唯一权威来源。
- 中心服读取 `STATE["ledger"]`、主数据库 `model_usage_logs`、已支付充值订单和已使用兑换码记录，归一化为统一账单记录后完成去重、分类和聚合。管理员手动充值从本次功能上线起同时写入账本。
- 本地客户端不重新计算指标，只格式化数值并渲染图表、筛选器和表格。
- 现有无参数 `GET /api/billing/ledger` 调用保持兼容。

### 6.2 数据流

1. 用户打开账户中心，客户端请求最近 30 天账单分析和第一页明细。
2. 中心服鉴权后读取当前用户余额、消费记录及可可靠还原的充值记录。
3. 归一化层统一时间、金额方向、状态、类型、模型 ID、任务 ID 和详情摘要。
4. 去重层消除同一业务在多个数据源中的重复记录。
5. 聚合层计算指标、趋势和类型分布。
6. 中心服返回经过 JSON Schema 校验的响应。
7. 客户端更新四项指标、柱状图、类型分布和明细表。
8. 用户调整全局日期或趋势粒度时刷新分析；调整明细筛选或页码时只刷新明细。

## 7. API 契约

### 7.1 `GET /api/billing/analytics`

查询参数：

- `startDate`：`YYYY-MM-DD`，可选。
- `endDate`：`YYYY-MM-DD`，可选。
- `groupBy`：`day` 或 `month`，默认 `day`。

响应核心字段：

```json
{
  "ok": true,
  "period": {
    "startDate": "2026-07-01",
    "endDate": "2026-07-30",
    "groupBy": "day",
    "timezone": "Asia/Shanghai"
  },
  "metrics": {
    "balance": 0,
    "totalConsumption": 0,
    "activeConsumptionDays": 0,
    "dailyAverage": 0,
    "videoTaskCount": 0,
    "videoAverage": 0
  },
  "trend": [
    {"bucket": "2026-07-30", "amount": 0}
  ],
  "distribution": [
    {"type": "video", "label": "视频生成", "amount": 0, "ratio": 0},
    {"type": "image", "label": "图片生成", "amount": 0, "ratio": 0},
    {"type": "voice", "label": "配音", "amount": 0, "ratio": 0},
    {"type": "other", "label": "其他", "amount": 0, "ratio": 0}
  ]
}
```

金额字段统一使用既有云豆精度规则，服务端计算使用定点数或 `Decimal`，避免浮点累计误差。

### 7.2 `GET /api/billing/ledger`

新增可选查询参数：

- `startDate`、`endDate`。
- `type`：`video|image|voice|other|recharge|refund`。
- `status`：`charged|refunded|recharged|failed`；不传表示全部。
- `page`：从 1 开始。
- `pageSize`：默认 20；客户端可选 20、50、100，服务端最大 100。

响应核心字段：

```json
{
  "ok": true,
  "balance": 0,
  "ledger": [
    {
      "id": "charge-record-id",
      "createdAt": "2026-07-30T12:00:00+08:00",
      "type": "video",
      "typeLabel": "视频生成",
      "modelId": "model-id",
      "taskId": "task-id",
      "detail": "片段视频生成",
      "change": -10,
      "balanceAfter": 90,
      "status": "charged",
      "statusLabel": "已扣费"
    },
    {
      "id": "refund-record-id",
      "createdAt": "2026-07-30T12:05:00+08:00",
      "type": "refund",
      "typeLabel": "退款",
      "modelId": "model-id",
      "taskId": "task-id",
      "detail": "片段视频生成退款",
      "change": 10,
      "balanceAfter": 100,
      "status": "refunded",
      "statusLabel": "已退款"
    }
  ],
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "total": 2,
    "totalPages": 1
  }
}
```

无任何新增参数时，接口继续提供现有字段，避免旧客户端失效。

## 8. 客户端页面设计

### 8.1 页面结构

1. 顶部指标区：四个紧凑指标块，显示云豆余额、期间总消耗、日均消耗、单条视频平均消耗。
2. 消费趋势区：日期范围、按日/按月切换和柱状图。
3. 类型分布区：使用四条横向占比条，分别显示四类消费的名称、金额和百分比，便于在窄窗口中直接比较。
4. 扣费明细区：筛选器、七列表格和分页控件。
5. 账户管理区：沿用现有控件和权限，仅管理员可见。

### 8.2 交互规则

- 首次进入显示加载状态，不使用旧请求结果覆盖新筛选结果。
- 全局日期范围影响四项指标、趋势和类型分布。
- 明细类型、状态和分页筛选独立，不改变顶部统计。
- 明细默认每页 20 条，可切换为 50 或 100 条；切换页大小后回到第 1 页。
- 状态筛选固定为全部、已扣费、已退款、已充值、失败；失败记录只展示审计信息，金额变动为 `0`，不进入余额变化和消费统计。
- 日期非法、网络失败或响应格式异常时保留上一次成功数据，并显示可重试错误提示。
- 图表使用客户端现有 `QPainter` 风格绘制，不新增 QtCharts 依赖。
- 类型分布的横向占比条使用同一金额上限计算长度；总消耗为零时四条均显示 `0` 和 `0%`，布局保持不变。
- 表格固定列宽与最小高度，长任务详情省略显示并通过悬停提示查看完整内容。

## 9. 错误处理与可观测性

- 中心服所有失败返回稳定错误码、错误编号和用户可理解提示。
- 服务端记录 JSON 结构化日志，包含事件名、错误编号、用户内部 ID、日期范围、分组方式、耗时、数据源行数、去重行数和异常堆栈。
- 日志不得记录令牌、密码、完整手机号、完整媒体 URL 或请求头。
- 客户端记录请求开始、成功、失败和过期响应丢弃事件，不记录鉴权凭据。
- 数据源部分失败时不静默返回不完整统计；返回明确错误，避免展示错误余额或错误消费总额。

## 10. 非功能性需求

- 查询延迟：最近 30 天、单用户常规数据量下，中心服 P95 不超过 800 ms；客户端请求后 1 秒内出现加载反馈。
- 并发目标：账单查询接口初始按 20 QPS 设计，不阻塞生成任务接口。
- 查询范围：单次最大 366 天，明细单页最大 100 条。
- 准确性：金额计算无浮点累计误差；重复记录不得重复计费；退款和充值不得进入消费统计。
- 可用性：账单统计失败不得影响生成、充值和用户管理功能。
- 安全性：只能读取当前授权账户数据；结构化日志必须脱敏。
- 资源限制：不涉及 GPU；中心服聚合过程应限制中间结果规模，避免无界加载历史流水。

## 11. 技术选型对比

| 选项 | 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A | 中心服统一聚合，客户端展示 | 单一统计口径、权限可靠、可复用、便于审计 | 需要新增中心服接口 | 采用 |
| B | 客户端拉取流水后本地聚合 | 中心服改动较少 | 流水不完整、口径易漂移、分页后无法准确统计 | 不采用 |
| C | 新建专用账单汇总表 | 大数据量查询快 | 需要迁移、回填和一致性维护，当前规模下过度设计 | 暂不采用 |

| 前端图表选项 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 复用 `QPainter` 自绘 | 无新增依赖，风格可与客户端一致 | 需实现坐标和空状态 | 采用 |
| 引入 QtCharts | 图表能力完整 | 新增部署依赖和包体风险 | 不采用 |
| HTML 图表嵌入 | 生态丰富 | 引入 WebView 和通信复杂度 | 不采用 |

## 12. 测试与质量门禁

### Phase 0：最小冒烟骨架

- 使用假余额、假内存账本和假 `model_usage_logs` 跑通“归一化 -> 去重 -> 聚合 -> API 响应 -> 客户端解析”。
- 冒烟必须覆盖一笔视频消费、一笔图片消费、一笔配音消费、一笔充值和一笔退款。
- 先记录失败点到 `docs/TROUBLESHOOTING.md`，修复后再进入完整实现。

### 自动化测试

- 统计单元测试：有消费天数日均值、零消费、跨月分组、退款/充值排除、视频任务去重、未知类型归类。
- API 契约测试：日期校验、最大跨度、鉴权、分页、旧无参数兼容、OpenAPI Schema。
- 数据源测试：多来源去重、部分数据缺字段、数据库不可用时明确失败。
- 充值追溯测试：微信充值、兑换码充值和管理员手动充值从上线后都产生正金额明细；不可可靠还原的历史管理员充值不生成伪造记录。
- 客户端测试：默认 30 天、按日/按月、筛选分页、管理员与非管理员显示规则、过期响应丢弃。
- 冒烟测试：假数据完整链路；部署前再使用测试账号验证真实只读账单查询。

## 13. 文档、部署与回滚

- 实现时同步更新 `docs/ARCHITECTURE.md`、`docs/API_REFERENCE.md`、`docs/DEPLOYMENT.md`、`docs/TROUBLESHOOTING.md`、`docs/openapi.yaml`、`docs/IMPLEMENTATION.md` 和 `CHANGELOG.md`。
- `docs/IMPLEMENTATION.md` 使用实现完成后的准确行号，提交前重新计算。
- 当前设计不涉及数据库结构变化，`migration.sql` 记录“无数据库迁移”即可，不创建虚假 SQL。
- 中心服代码变更发布前保留上一个稳定版本或镜像标签；新账单接口错误率超过 1% 时回滚中心服。
- 客户端保留上一个稳定包；页面严重异常时可回滚客户端，旧账单接口保持可用。
- 实现完成后不自动重启本地客户端。中心服需要重启才能加载新接口，实际重启和部署时间须单独确认。

## 14. 验收标准

- 默认打开账户中心时显示最近 30 天数据。
- 四项指标与原始账单核对一致。
- 日均消耗只除以有消费记录的天数。
- 充值和退款只出现在明细，不进入任何消费统计。
- 同一笔退款在明细中同时保留原扣费负金额记录和退款正金额记录，并可通过任务 ID 追溯关联。
- 上线后的三类充值均显示正金额“已充值”明细；历史记录仅展示可可靠还原的数据。
- 趋势可按日、按月切换，并可选择自定义日期。
- 类型分布只显示视频生成、图片生成、配音、其他。
- 类型分布采用四条横向占比条，并同时显示金额和百分比。
- 明细包含时间、类型、模型 ID、任务详情、实扣/变动、扣后余额、状态，并支持筛选和分页。
- 状态筛选包含全部、已扣费、已退款、已充值、失败；失败记录不计入余额变化或消费统计。
- 管理员原有账户管理功能保留；普通用户和企业用户仍不可见。
- 旧客户端继续能够调用无参数账单明细接口。
- 自动化测试、契约测试和假数据端到端冒烟通过，相关日志可用错误编号追踪且不泄露敏感信息。

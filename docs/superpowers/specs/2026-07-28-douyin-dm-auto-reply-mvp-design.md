# 抖音指定客户私信全自动回复 MVP 设计

## 1. 背景与目标

当前「私信 / AI 销售」页面已经有半自动能力：运营填写客户主页链接和客户消息，AI 生成回复后由运营确认发送；也有「全自动回复」开关，但自动收信任务 `douyin.dm.inbox` 没有在中心服和本地浏览器执行器中接通，点击后容易表现为无反应。

本次 MVP 目标是补齐一个可上线、可观测、可回滚、可追溯的最小闭环：只针对运营填写的单个抖音客户主页链接，每 20 秒检查该客户私信会话；如果客户发来纯文本消息，系统在 5 分钟合并窗口内生成一条回复并自动发送。不做全量私信列表扫描，不做多客户并发托管。

## 2. 已确认需求

- 用户必须先填写指定客户抖音主页链接。
- 开启全自动后，每 20 秒后台打开或检查该客户私信会话。
- 只处理客户发来的纯文本私信。
- 5 分钟内同一客户连续发多条纯文本时，合并成一次 AI 回复。
- 图片、语音、视频、表情、卡片、分享链接等非文本内容不自动回复，只提示人工查看。
- 允许本地浏览器在后台打开目标客户私信页读取最新消息。
- 自动回复成功、失败、跳过、转人工都要有清晰 UI 状态和结构化日志。

## 3. 非目标

- 不扫描全量私信列表。
- 不自动选择多个客户。
- 不接入外部客服系统。
- 不自动发送「已转人工」之类话术。
- 不绕过抖音登录、风控或页面权限限制。
- 不保存 Cookie、Token 或完整私信正文到中心服日志。

## 4. 方案对比

| 方案 | 优点 | 风险 | 结论 |
|---|---|---|---|
| A. 只修复开关提示 | 改动最小，能避免误解 | 没有真实全自动能力 | 不采用 |
| B. 指定客户主页链接轮询 | 范围小，复用现有发送链路，风险可控 | 依赖抖音私信页 DOM，后续可能需要维护选择器 | 采用 |
| C. 全量私信列表扫描 | 自动化程度高 | 涉及多客户状态、误发、风控、客服转派，首版风险过大 | 暂不采用 |

## 5. 架构设计

新增一条本地浏览器任务类型：

```text
DMPage -> /api/local-browser/task(douyin.dm.inbox)
       -> local_browser_worker
       -> local api_server /api/douyin/dm/inbox
       -> Playwright 打开指定客户私信会话
       -> 返回最新消息
       -> DMPage 合并、判重、AI 生成、调用 douyin.dm 发送
```

中心服只负责任务调度、权限校验、审计和任务回执，不直接读取抖音页面。真正读取和发送均在用户本机浏览器完成，继续沿用当前「本机浏览器 + 用户 IP」模式。

## 6. 组件边界

### 6.1 `backend/api_server.py`

新增本地接口 `/api/douyin/dm/inbox`，只接受 POST。

请求字段：

- `target`：客户主页 URL，必填。
- `limit`：最多返回最近消息数，默认 10，最大 20。
- `sinceFingerprint`：客户端上次处理的消息指纹，可选。

响应字段：

- `ok`
- `platform: "douyin"`
- `target`
- `messages`
- `nonTextCount`
- `needLogin`
- `error`

每条消息返回：

- `id`：稳定消息 ID，拿不到时用本地指纹。
- `fingerprint`：脱敏判重指纹。
- `direction`：`customer` 或 `me`。
- `kind`：`text`、`image`、`voice`、`video`、`card`、`emoji`、`unknown`。
- `text`：仅纯文本消息返回，最多 1000 字。
- `createdAtText`：页面可见时间文本，拿不到为空。

### 6.2 `backend/local_browser_worker.py`

新增任务映射：

```text
douyin.dm.inbox -> /api/douyin/dm/inbox
```

同时把能力加入 `CAPABILITIES`，用于中心服筛选在线本地执行器。

### 6.3 `backend/central_server.py`

新增中心服白名单：

```text
douyin.dm.inbox
```

创建任务时继续做企业成员权限校验、在线客户端筛选、审计日志。审计日志只记录任务类型、客户 URL 指纹、消息数量和错误码，不记录完整私信正文。

### 6.4 `backend/matrix_native_client.py`

完善 `DMPage`：

- 开关打开前校验客户主页链接。
- 每 20 秒提交 `douyin.dm.inbox`。
- 对 `customer/text` 消息做去重。
- 5 分钟合并窗口内缓存客户文本，不逐条回复。
- 到达回复窗口后，把缓存文本合并为一条客户消息交给 `ai_sales_reply()`。
- AI 成功后调用现有 `douyin.dm` 自动发送。
- 非文本消息标记为人工查看，不自动回复。
- 状态栏显示最近检查时间、缓存条数、下次可回复时间、最近错误。

## 7. 转人工规则

MVP 中「转人工」不是派单系统，而是自动化的安全降级状态：

- 收到非文本消息时，不自动生成也不自动发送。
- 页面提示：`收到非文本私信，请人工查看该客户会话。`
- 本地会话记录追加一条 `manual_required` 状态。
- 自动开关保持开启；后续如果客户继续发纯文本，仍可进入自动回复合并窗口。
- 不向客户发送任何「已转人工」话术。

## 8. 合并与限频规则

- 轮询间隔：20 秒。
- 同一客户自动回复间隔：5 分钟。
- 如果距离上次自动回复不足 5 分钟，新增纯文本进入待回复缓存。
- 到达 5 分钟窗口后，把缓存中的多条文本按时间顺序合并，格式为多行客户消息。
- 同一消息指纹只处理一次。
- AI 生成失败时不发送，缓存保留为待处理并显示错误。
- 发送失败时不标记为已完成，避免误判。

## 9. 错误处理与可观测性

新增或复用结构化日志事件：

- `douyin_dm_inbox_poll_started`
- `douyin_dm_inbox_poll_finished`
- `douyin_dm_inbox_message_skipped`
- `douyin_dm_auto_reply_buffered`
- `douyin_dm_auto_reply_sent`
- `douyin_dm_auto_reply_failed`
- `douyin_dm_auto_reply_manual_required`

日志必须 JSON 化并脱敏：

- 不记录 Cookie、Authorization、完整主页 URL、完整私信正文。
- 对客户主页 URL、消息正文使用 SHA-256 截断指纹。
- 允许记录文本长度、消息数量、错误码、任务 ID、耗时、平台。

UI 错误提示按用户可处理方式归类：

- `not_authenticated`：请重新登录抖音。
- `local_browser_offline`：请启动本地执行器。
- `dm_inbox_button_not_found`：无法打开私信入口，可能是页面结构变化或账号权限限制。
- `dm_inbox_messages_not_found`：未读取到会话消息。
- `dm_auto_reply_ai_failed`：AI 生成失败，未发送。
- `dm_auto_reply_send_failed`：发送失败，请人工检查。

## 10. 非功能性需求

| 项目 | 目标 |
|---|---|
| QPS | 单客户端每 20 秒最多 1 次收件箱检查；不支持多客户并发托管 |
| 延迟 | 收到文本后 0 到 5 分钟内合并回复；AI 和发送链路按现有超时处理 |
| 内存 | 客户端每客户缓存最近 100 条消息指纹和待回复文本，额外内存低于 5 MB |
| GPU/显存 | 0 MB，本功能不使用 GPU |
| 安全 | 不自动处理非文本消息；不记录敏感正文；不绕过平台登录 |
| 可回滚 | 回滚 `api_server.py`、`local_browser_worker.py`、`central_server.py`、`matrix_native_client.py` 和测试/文档即可 |
| 可追溯 | 每次轮询和发送都有任务 ID、消息指纹、错误码和结构化日志 |

## 11. 测试策略

### Phase 0 冒烟骨架

先用假数据跑通最小链路：

1. 假 `douyin.dm.inbox` 返回两条客户文本和一条非文本消息。
2. 客户端缓存文本消息。
3. 时间窗口到达后调用假 AI 生成。
4. 调用假 `douyin.dm` 发送。
5. 非文本消息只触发人工提示，不发送。

### 单元与契约测试

- 中心服允许创建 `douyin.dm.inbox` 任务。
- 本地执行器包含 `douyin.dm.inbox` 映射和能力声明。
- 本地 `/api/douyin/dm/inbox` 缺少 `target` 时返回明确错误。
- 客户端对 5 分钟内多条文本只发送一次。
- 重复消息指纹不会重复回复。
- 非文本消息不触发发送。
- AI 失败不触发发送。
- 本地执行器离线、抖音未登录、页面读取失败时 UI 文案明确。

### 冒烟验证

真实抖音页面验证受登录态、页面结构和风控影响。若具备测试账号，则只对指定客户主页做读取和发送冒烟；若不具备测试账号，最终报告必须明确真实页面未验证，并保留假数据和单元测试结果。

## 13. 验收标准

- 未填写客户主页链接时，开关不会表现为无反应，页面给出明确提示。
- 填写客户主页链接并开启后，状态栏显示轮询状态和最近检查时间。
- 收到纯文本消息后，5 分钟内多条文本被合并成一次自动回复。
- 非文本消息不发送，页面提示人工查看。
- 发送成功后本地会话显示 AI 回复，重复轮询不会再次发送同一回复。
- 本地执行器离线、抖音未登录、读取失败、AI 失败、发送失败都有明确错误。
- 相关单元测试、契约测试、编译检查通过。
- 日志和审计记录可追踪任务，但不泄漏完整私信正文或认证信息。
